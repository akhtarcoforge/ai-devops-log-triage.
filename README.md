# ai-devops-log-triage.
# 🚀 AI-Powered Azure DevOps Pipeline Build Log Triage Framework

An event-driven, security-first AIOps automation framework that intercepts failed Azure DevOps pipeline builds, extracts the relevant error stack traces, and leverages an open-source Local LLM (Llama 3.2 via Ollama) to output structured, 3-step root-cause remediation summaries. 

By running the LLM locally on infrastructure, this design guarantees **100% corporate data privacy**, ensuring sensitive logs, token strings, and environment variables never leave your secure perimeter. It can also scale seamlessly into autonomous self-healing via the **Cursor Cloud Agents API**.

---

## 🏗️ Architecture Flow
[Azure DevOps Build Failure]
│
▼ (Webhook Trigger / Script Invocation)
[Python Triage Engine]
│
├─► 1. Authenticates via Azure DevOps REST SDK
├─► 2. Identifies exact failed steps & extracts final 50-70 log lines
└─► 3. Packages raw stack trace into structured prompt engineering payload
│
▼ (Secure HTTP POST locally via Port 11434)
[Local Llama 3.2 Model Engine]
│
▼ (Generates 3-step deterministic markdown resolution metadata)
[Teams / Slack Webhook Gateway] ──► Instant Notification to Engineering Channels

### Prerequisites
* **macOS** with Homebrew installed.
* **Python 3.10+**

### Step-by-Step Workspace Provisioning

1. **Install and Initialize Ollama:**
   ```bash
   brew install ollama
   brew services start ollama
   ```

2. **Download the Llama 3.2 3B Model:**
   ```bash
   ollama run llama3.2:3b
   # Once the download completes and the prompt (>>>) opens, type /exit and press Enter.
   ```

3. **Clone & Set Up the Isolated Python Virtual Environment:**
   ```bash
   mkdir -p ~/DevOps/adv-log-parser && cd ~/DevOps/adv-log-parser
   python3 -m venv .venv
   source .venv/bin/activate
   ```

4. **Install Enterprise Core SDK Dependencies:**
   ```bash
   pip install --upgrade pip
   pip install azure-devops ollama msrest requests
   ```

## 🧠 2. Code Mechanics & Function Execution

The Python automation engine (`local_triage.py`) consists of three core operational layers:

### A. Ingestion Layer: `get_pipeline_logs(build_id)`
* **What it fetches:** Connects to the Azure DevOps API endpoints using a securely provisioned Personal Access Token (PAT). It queries the target project's build history timeline for the provided `build_id`.
* **The Logic:** Iterates across all execution records to find the specific tasks flagged as `"failed"`. It calls `get_build_log_lines` to ingest the raw console track logs of that step, keeping only the final 50–70 lines—capturing the exact window where compilation crashes or dependency errors occur without inflating token windows.
* **Fallback Framework:** If no Azure environment keys are found, it triggers a **Mock Mode** using an authentic, multi-error TypeScript/Docker crash log for local staging and isolated validation testing.

### B. Analytical AI Layer: `ask_local_llama(step_name, log_content)`
* **What it does:** Structures a strictly typed system prompt wrapper enclosing the raw log string.
* **The Communication:** Establishes a local API loop socket connecting to `http://localhost:11434/api/chat`. It enforces a low temperature boundary (`temperature=0.2`) on the model, suppressing creative hallucinations and forcing factual, deterministic answers.
* **What it outputs:** Generates a structured technical triage summary detailing:
  1. **What Failed:** Pinpoints exact runtime syntax issues, file names, or broken libraries.
  2. **Root Cause:** Translates complex system stack footprints into clear architectural problems.
  3. **Remediation:** Provides explicit copy-paste shell strings or configuration adjustments needed to restore stability.

### C. Orchestration Layer: `main()`
* Reads the incoming arguments from your command prompt shell loop, casts the variable safely into an integer object format, handles operational exception boundaries, and prints the formatted AIOps telemetry report straight to the output display socket.

## 🤖 3. Enterprise Automation & Microsoft Teams Integration

To run this pipeline completely hands-free in a production workspace and push automated alerts to your engineering group whenever a build breaks, follow this guide:

### Step A: Configure a Microsoft Teams Incoming Webhook
1. Open your target channel in Microsoft Teams, click the three dots (`...`), and select **Connectors** (or *Manage Channel -> Apps -> Webhooks*).
2. Find **Incoming Webhook**, name it `AIOps Triage SRE`, upload an icon, and click **Create**.
3. **Copy the unique Webhook URL** generated by Teams.

### Step B: Modify the Script to Forward the Triage Payload
Incorporate this lightweight routing function directly into your `local_triage.py` script:

```python
import requests

TEAMS_WEBHOOK_URL = os.getenv("TEAMS_WEBHOOK_URL")

def dispatch_to_teams(triage_report):
    """Fires a POST request sending the markdown AI summary directly into Microsoft Teams."""
    if not TEAMS_WEBHOOK_URL:
        print("⚠️ TEAMS_WEBHOOK_URL variable missing. Skipping channel dispatch.")
        return

    # Payload structured explicitly to render clean Adaptive Cards inside Teams channels
    payload = {
        "@type": "MessageCard",
        "@context": "http://schema.org",
        "themeColor": "E81123", # Production Red Alert Flag
        "summary": "AI Pipeline Triage Notification",
        "sections": [{
            "activityTitle": "🤖 Automated AIOps SRE Triage Report",
            "activitySubtitle": "Azure Pipeline Execution Failure Caught",
            "text": triage_report.replace("\n", "<br>") # Matches Teams HTML parsing limits
        }]
    }
    
    response = requests.post(TEAMS_WEBHOOK_URL, json=payload)
    if response.status_code == 200:
        print("🚀 Triage report dispatched smoothly to Microsoft Teams channel!")
```

*Call `dispatch_to_teams(triage_report)` inside your script's execution loops right after the model response returns.*

### Step C: Trigger via Azure DevOps Service Hooks (Production Webhook Trigger)
Instead of typing commands manually, tie this script into an **automated event-driven daemon web-handler**:

1. In Azure DevOps, go to **Project Settings -> Service Hooks**.
2. Click **Create Subscription (+)** and choose **Webhooks**.
3. Set the trigger event to: **Build completed** and filter the status criteria to **Failed**.
4. Set your Action to forward the JSON payload to an internal endpoint (e.g., an internal webhook receiver script, AWS Lambda, or an Azure Function runner) hosting your Python script execution stack.
5. Provide your system credentials globally within your runtime host environment:
   ```bash
   export AZURE_DEVOPS_PAT="your-pat-string"
   export AZURE_DEVOPS_ORG_URL="https://azure.com"
   export AZURE_PROJECT_NAME="your-project"
   export TEAMS_WEBHOOK_URL="https://your-teams-webhook-endpoint"
   ```

Now, the entire pipeline is **100% automated**. A pipeline crashes, the webhook fires, the script hooks the logs, Llama diagnoses it locally on your cluster network, and your engineers get a complete resolution plan in Teams within 5 seconds!
